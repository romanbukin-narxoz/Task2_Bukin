# Как закончить и сдать Task 2

Это продолжение Task1_Report_Bukin_FINAL. Тема и три алгоритма сохранены.

## 1 Распакуй проект
Распакуй Task2_Bukin.zip. Внутри папки Task2_Bukin лежат файлы проекта.
Включи показ скрытых файлов, чтобы видеть .gitignore и .python-version.

## 2 Проверь запуск на своём компьютере
Установи Python 3.12. Открой папку проекта, нажми на адресную строку Проводника,
введи powershell и нажми Enter. Скопируй по очереди:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe src\benchmark.py
```

Должно появиться OK: 3 benchmark rows и предупреждение о тестовых данных.
В results/smoke появятся результаты. Это проверка кода, не научные результаты.
Сфотографируй свой успешный запуск, если преподаватель просит подтверждение.

## 3 Создай публичный репозиторий
На GitHub создай репозиторий с именем Task2_Bukin и видимостью Public.
Оставь автоматическое создание README, .gitignore и LICENSE выключенным — они уже есть.
Скопируй получившуюся ссылку вида https://github.com/ТВОЙ_ЛОГИН/Task2_Bukin.
Открой docs/Methodology_Card.md в Блокноте и замени строку TO BE FILLED... на эту ссылку.

## 4 Загрузи файлы с помощью Git
Если Git ещё не установлен, установи Git for Windows. В той же папке проекта:

```powershell
git init
git config user.name "Roman Bukin"
git config user.email "ТВОЙ_EMAIL_ИЛИ_NOREPLY_ИЗ_GITHUB"
git add README.md LICENSE .gitignore .python-version requirements.txt config.json configs src data
git commit -m "Add reproducible spam classification benchmark and sample"
git add docs
git commit -m "Document methodology hypotheses and experiment protocol"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/Task2_Bukin.git
git push -u origin main
```

Перед запуском замени email и ТВОЙ_ЛОГИН своими значениями. При входе используй
обычное окно авторизации GitHub. Токены и пароли в файлы проекта не записывай.
Команды рассчитаны на новый репозиторий. Если он уже существует, не перезаписывай его.
Коммиты создаются при твоей реальной загрузке файлов; история прошлой работы не выдумывается.

## 5 Проверь и сдай
Открой публичную ссылку без входа в аккаунт. Убедись, что видны README,
.gitignore, requirements.txt, src, config.json, data/sample и docs.
Папок .venv и results там быть не должно.
В LMS приложи docs/Methodology_Card.md и публичную ссылку на репозиторий.
Markdown прямо разрешён заданием, перевод в PDF не обязателен.
Не отправляй ZIP вместо ссылки: ZIP — это заготовка для загрузки проекта.
